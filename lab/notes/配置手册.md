## 1. 通道一：局域网直连（默认，已完成验证）

- 桌面 DSH → **设置 → 手机** → 顶部二维码（`/api/mobile/qr.svg`）。
- 手机 App 点「扫码配对」扫它（或相册识别/手动输入链接）。
- 手机与电脑同一局域网即可用（默认经 `0.0.0.0:47896` 透明代理访问，Host 改写穿栅栏；端口被占自动 +1）。

常见坑：
- 手机连不上但电脑正常 → 看设置页「地址」列出的 IP；若是虚拟网卡（Radmin/Tailscale/WSL）地址，到插件配置 `lanIps` 显式指定真实网卡 IP。
- 防火墙：放行 `node.exe`（DSH 后端进程）入站，或添加规则「DSH Desktop Mobile」放行 TCP 47896。

### 1.1 虚拟组网（Tailscale / ZeroTier 等）—— 手动放行开关

默认策略**剔除全部虚拟网卡**（防止把手机不可达的地址铸进二维码）。使用 Tailscale/ZeroTier 等组网方案时，**手动放行**即可让虚拟地址进配对候选：

- **桌面**：设置 → 手机 → 「虚拟组网接口」卡片 → 下拉选择：
  - `自动剔除（默认）` —— 保持默认
  - `放行全部虚拟接口` —— Tailscale/ZeroTier/Radmin/WSL 全进候选
  - `仅 Tailscale` / `仅 ZeroTier` —— 只放行对应接口
  - `自定义` —— 逗号分隔接口名（如 `Tailscale, ZeroTier`）
  - 保存即生效（下次配对/二维码重新采样，无需重启）
- **手机**：设置 → 连接信息卡 → 「包含虚拟组网接口」开关（等价放行全部/恢复默认）。
- 高级：也可在 `cordis.patch.yml` 插件配置写 `netconf: { virtual: true }` 或 `virtual: ['Tailscale']` 作默认值（运行时开关优先）。

> 细节：放行的组网接口豁免 CGNAT 剔除——**Tailscale 默认段 100.64.0.0/10 就是 CGNAT**，普通策略会误伤；link-local（169.254）与代理 TUN 假 IP（198.18/198.19）即使放行也仍剔除。候选顺序恒为「物理接口在前、放行虚拟在后」，首选地址仍是真实网卡。

## 2. 通道二：中继远程（异地 / 蜂窝网）

原理：宿主**主动出站**连到你自己的中继（wss），手机从任何网络经中继访问宿主；宿主断网自动重连。

### 2.1 起中继（选一种）

**A. 直接跑（本机/内网调试）**
```bash
node C:\Users\lcl\Desktop\DSH\relay\bin\dsh-mobile-relay.mjs --port 8443 --host 0.0.0.0 --key <你的密钥>
```
状态页：`http://<中继IP>:8443/`（在线实例、流量）。

**B. Docker（公网 VPS，推荐）**
```bash
cd C:\Users\lcl\Desktop\DSH\relay
RELAY_KEY=$(openssl rand -hex 32) docker compose up -d
```
> Windows 没有 openssl 可用 PowerShell：`-join ((1..32) | ForEach-Object { '{0:x2}' -f (Get-Random -Max 256) })`

**C. systemd（裸机 Linux）**
见 `relay\deploy\dsh-mobile-relay.service`，把密钥写进 `/etc/dsh-mobile-relay.key`（chmod 600）。

**D. 公网 TLS 反代（必须，否则密钥明文裸奔）**
Nginx 示例（`relay\README.md` 有完整版；关键是转发 `Upgrade`/`Connection` 头）：
```nginx
server {
  listen 443 ssl;
  server_name relay.example.com;
  ssl_certificate /etc/letsencrypt/live/relay.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/relay.example.com/privkey.pem;
  location / {
    proxy_pass http://127.0.0.1:8443;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

- 勾选 **启用中继** → **保存并生效** → 状态灯变绿「● 已连接」

配置落盘 `dsh-home\mobile-companion\relay.json`（原子写；yaml 里的 `config.relay` 仅作默认值）。

### 2.3 手机接入（任意网络）

- 配对二维码已自动包含中继地址（候选顺序：局域网代理 → 中继 → 直连），App 自动探测可达项；
- 或复制卡片上的访问地址 `https://relay.example.com/i/home-pc` 到手机浏览器/App 直接打开。

### 2.4 验证（中继）

手机开飞行模式 + 关 Wi-Fi（纯蜂窝）：新建任务 → 发消息 → 看流式回复 → 上拉历史。全程无感。

### 2.6 公网入口（网关端口映射，手机零安装）—— ⚠️ 需先确认有公网 IP

> **实测结论（2026-09-26）：本网络为双层 NAT，此方案不可用。** 请先按 2.6.1 自检，再决定是否投入。

如果你的 OpenVPN 网关（路由器）本身有公网 IP，且管理面板支持端口映射，则手机**完全不用装任何软件**：

1. **路由器面板**配置端口映射（入口名常见：「虚拟服务器」「端口映射」「NAT 转发」）：
   - 公网端口：`47896`（或任意未用端口，避开 1194）
   - 内网 IP：`10.80.12.2`（宿主的 OpenVPN 虚拟 IP，网关可见）
   - 内网端口：`47896`（DSH 代理端口）
   - 协议：`TCP`
2. **桌面**：设置 → 手机 → 「📱 配对」tab → **公网入口**卡片 → 填 `http://117.36.156.68:47896`（换成你配置的公网端口）→ 保存
3. **手机**：刷新配对二维码 → DSH App 扫码 → 候选里出现公网地址 → 异地（蜂窝/任意 WiFi）零安装直连

原理：手机 → 网关公网端口 → 网关转发到宿主的 47896（OpenVPN 隧道内）→ 插件透明代理改写 Host → DSH 栅栏通过。**不需要 client-to-client**（服务器→客户端流量天然可达）。token 交换也走公网入口，异地扫码不会落空。

#### 2.6.1 先做这一步：判断自己是不是双层 NAT（3 条命令）

路由器上配完端口映射后，**在宿主 PowerShell** 执行：

```powershell
# ① 路由器 LAN 口网关（通常是 192.168.5.1）
Get-NetIPConfiguration | Where-Object {$_.IPv4DefaultGateway} |
  Select-Object InterfaceAlias,@{n='IP';e={$_.IPv4Address.IPAddress}},@{n='GW';e={$_.IPv4DefaultGateway.NextHop}}

# ② 查询入户公网 IP（走 HTTPS，不会被运营商 DNS 劫持）
(Invoke-RestMethod 'https://api.ipify.org?format=json' -TimeoutSec 8).ip

# ③ 在浏览器登录路由器 → 网络 → WAN，看「当前网络状态」里的 IPAddress
#    或直接读取路由器状态接口（ZTE 示例，登录后同源执行）：
#    fetch('/?_type=vueData&_tag=vue_mainwan_data') → IPAddress / GateWay
```

**判读表：**

| WAN 口 IPAddress | 结论 | 该怎么办 |
| --- | --- | --- |
| 与 ② 的公网 IP **相同** | ✅ 单层 NAT，有公网 IP | 端口映射可用，按上面 1~3 步走 |
| 是 `10.x` / `100.64~127.x` / `172.16~31.x` / `192.168.x` 等**私网地址** | ❌ **双层 NAT**，入向被上游光猫/运营商拦住 | **放弃此方案**，改走 §2.5 OpenVPN 或 §2 中继 |

> 本机实测：路由器 WAN = `192.168.1.9`，上游网关 `192.168.1.1` 是光猫（`Server: Boa/0.94.13`）→ 属**双层 NAT**；对应 DDNS 状态恒为 `Disconnected`，公网域名解析到的是 pubyun 免费档占位 IP。这是宽带环境限制，**改路由器配置无法解决**。

#### 2.6.2 如果没有公网 IP：两个真正可行的零安装通道

| 通道 | 原理（为什么能穿透双层 NAT） | 手机装软件 | 手册位置 |
| --- | --- | --- | --- |
| **OpenVPN 隧道**（推荐） | VPN 网关有公网 IP，宿主作为客户端**主动出向**拨号，服务端下发路由；手机连同一份配置即同网段 | 需装 OpenVPN Connect | §2.5 |
| **自建中继** | 宿主**主动出向** WSS 连中继，全程无需入向放通 | 不需要 | §2 |

> 若你的 OpenVPN 服务端与 ZTE 路由器在同一台设备（或同一公网出口），注意 §2.6 的公网入口依赖「网关能转发到 VPN 虚拟 IP」；部分固件无法向 tun 接口转发，此时请直接用 §2.5（手机连 VPN），不要依赖端口映射。

### 2.5 OpenVPN 通道（自建 VPN 组网，已内置）

有自建 OpenVPN 服务器（国内 VPS 亦可）时，宿主与手机连入同一 VPN 网段，手机即可像局域网一样直连宿主——**另一种"不同网络 + 无公网 IP"的路径**。

- **宿主侧**（插件内置，无需重启）：
  1. 桌面 设置 → 手机 → 「🌐 组网」tab → **OpenVPN 通道**卡片
  2. 「上传 client.ovpn」选择你的 OpenVPN 客户端配置（已预置时可跳过；配置落盘 `dsh-home\mobile-companion\ovpn\client.ovpn`）
  3. 点「连接」→ 状态灯变绿「● 已连接 10.80.12.2」；**虚拟 IP 自动进入配对候选**
  4. 「断开」即停
  - 依赖：本机已装 OpenVPN 客户端（社区版 `C:\Program Files\OpenVPN\bin\openvpn.exe` 或 OpenVPN Connect；未装时卡片会提示）
- **手机侧**：安装 **OpenVPN Connect**（应用商店/官网），导入**同一份 client.ovpn** → 连接 → 手机获得同网段虚拟 IP → 打开 DSH App 扫码/重新配对 → 候选地址已含宿主虚拟 IP，直连即用
- 已验证：真实拨号 `Initialization Sequence Completed`，分配 `10.80.12.2`（网段 10.80.12.0/24），插件自动注入候选
- 安全：`client.ovpn` 内含私钥（证书认证），属凭证——仅落盘插件数据目录、界面不回显；请确认服务器归属可信（服务器管理员可见 VPN 内明文流量）

## 3. 通道三：推送通知（FCM，需 Firebase 凭据）

> 代码已就绪（App 特性开关 + 插件注册 API + 免打扰 + 投递工具），**只差你填 Firebase 凭据**。
> 未配置时 App 静默跳过推送注册，其余功能不受影响。

### 3.1 手机侧：接入 FCM（一次性）

1. **Firebase 控制台**（console.firebase.google.com）→ 新建项目（或复用）→ **添加应用 → Android**：
   - 包名填 `com.dsh.mobile`（与 `mobile-app\capacitor.config.json` 的 `appId` 一致）
   - 下载 **google-services.json** → 放入 `C:\Users\lcl\Desktop\DSH\mobile-app\android\app\`
2. 安装推送原生插件：
   ```bash
   cd C:\Users\lcl\Desktop\DSH\mobile-app
   npm install @capacitor/push-notifications@6
   npx cap sync android
   ```
3. Android Gradle 接入（按插件文档两步）：
   - 根 `android\build.gradle` 的 `buildscript.dependencies` 加
     `classpath 'com.google.gms:google-services:4.4.2'`
   - `android\app\build.gradle` 文件顶部加 `apply plugin: 'com.google.gms.google-services'`
4. 重新打包：
   ```bash
   cd android
   .\gradlew assembleRelease
   ```
   产出 `app\build\outputs\apk\release\app-release.apk` → 安装。
5. 配对后 App 会自动：请求通知权限 → 拿 FCM 令牌 → 上报到插件
   （`/api/mobile/push/register`，写入 `dsh-home\mobile-companion\push.json`）。
   桌面 **设置 → 手机 → 通知 / 免打扰** 卡片可见「N 台设备已注册推送」。

### 3.2 服务端：投递凭据（二选一）

**推荐：HTTP v1（服务账号）**
Firebase 控制台 → 项目设置 → 服务账号 → **生成新私钥** → 保存 JSON（如 `firebase-service-account.json`）。

**简单：Legacy 服务器密钥**
Firebase 控制台 → 项目设置 → 云消息 → **服务器密钥**（旧版）。

### 3.3 发通知


### 3.4 自动触发建议

推送是「投递」，触发点由你决定，例如：
- **任务计划/计划任务**：DSH 任务完成后执行一段脚本调 `dsh-push`（把会话 ID 拼进 `--url`）。
- **bot-gateway**：机器人回复成功后顺带推一条。
- **cron**：每日提醒等。
工具尊重每设备的**免打扰窗口**（跨午夜支持），`--force` 可绕过。

## 4. 免打扰

- 桌面 **设置 → 手机 → 通知 / 免打扰**：每台已配对设备一个开关 + 起止时间（`HH:MM`，支持跨午夜，如 22:00–08:00）。
- 数据落盘 `push.json` 的 `dnd` 段；`dsh-push` 默认尊重（窗口内跳过），`--force` 忽略。
- 校验：非法时间（如 25:00）、起止相同都会被拒（400 + 中文原因）。

## 7. 常见问题

| 症状 | 处理 |
|---|---|
| App 提示 `连接后端服务失败(Cleartext HTTP ...)` | 已修复（v0.2.1+ 放行明文）；请装 v0.2.3 |
| 设备注册失败 HTTP 401 | 已修复（v0.2.2/v0.2.3 凭据链）；仍出现请开 USB 调试看 `chrome://inspect` 里 `[DSH]` 日志 |
| 扫码显示环回地址连不上 | 桌面 Ctrl+R 刷新 GUI 重取二维码（历史 bug 已修：二维码载荷现与 pair-info 一致） |
| 中继卡片「连接失败」 | 核对密钥/地址；中继机防火墙放行端口；`ws://` vs `wss://` 与反代一致 |
| 中继 502（离线实例） | 宿主没连上：看桌面卡片状态灯；宿主断网会自动重连 |
| 手机在 LAN 但走中继很慢 | 候选顺序局域网代理在前，App 会优先直连；或删掉实例重扫 |
| 推送没反应 | ① 检查 App 设置里权限；② 桌面「通知/免打扰」卡片看是否已注册；③ `dsh-push --dry-run` 看是否被免打扰拦截；④ 确认 `--url` 里的 origin 手机可达 |
| 端口 47896 被占 | 插件自动 +1 并在二维码/载荷中反映，以载荷为准 |
| 插件改了没生效 | 抬挂载 `?v=`（§6.1）；移动端刷新页面即可 |
| 路由器 DDNS 一直「未连接 / Disconnected」 | **先查是不是双层 NAT**（§2.6.1）。路由器 WAN 口拿到的是私网地址（如 `192.168.1.9`）时，DDNS 服务器会拒登，端口映射也穿不过上游光猫 → 改走 §2.5 OpenVPN 或 §2 中继，不要继续折腾 DDNS |
| 域名能 ping 通但连不上 DSH | 解析到的是 DDNS 免费档占位 IP（如 pubyun 的 `118.184.179.97`）而非你家公网 IP，说明 DDNS 未真正登记 → 同上，属双层 NAT |
| 端口映射已在路由器配好，外网仍不通 | 映射只穿透了第一层；上游光猫那层无权限配置 → 走 OpenVPN / 中继（主动出向，天生穿透 NAT） |
| OpenVPN 显示已连接，手机仍连不上 | ① 手机需装 OpenVPN Connect 并导入**同一份** `client.ovpn`；② 确认手机拿到同网段 IP；③ 桌面「📱 配对」重新扫码（虚拟 IP 会自动进候选） |

## 8. 安全须知

- **中继密钥即特权**：持 `--key` 者能把任意宿主接进你的中继 → 公网务必 `openssl rand -hex 32` 级强密钥 + HTTPS 反代。
- **relay.json / push.json 含密钥与 FCM token**：仅本机可读，勿进 git、勿发截图。
- 手机解除配对（桌面撤销）→ 设备 HMAC 立即失效、推送令牌一并清除；Cookie 残留最长 30 天由产品会话策略控制。
- 免打扰不加密，只是投递策略；FCM 传输走 Google 基础设施加密通道。
