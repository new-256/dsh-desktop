## 三、本次新发现：`%20` 路径 bug（连带附带问题3 + 问题4）

### 3.1 bug 现场
dsh-bot-gateway 包内 **5 处**用 `new URL(import.meta.url).pathname` 构造文件路径：

| 文件 | 行号 | 影响 |
|------|------|------|
| screen-watch.js | 156 | 捕获脚本路径 %20 不解码 → "脚本缺失"，桌面监控/`/桌面` 命令降级失效 |
| util.js | 19 | DSH_HOME 标志物探查失败 → getDshHomeDir() 降级 runtime-data |
| util.js | 37 | 同上（兜底路径也含 bug） |
| core.js | 191 | getPaths() try1 标志物探查失败 |
| core.js | 216 | getPaths() 兜底路径也含 bug |

### 3.2 bug 本质
```js
// ❌ 旧写法（不解码 %20）
const dir = new URL(import.meta.url).pathname.replace(/^\/([A-Za-z]:)/, '$1');
// 输出: C:/Users/lcl/AppData/Roaming/DSH%20Desktop/dsh-home/...
// existsSync → false（路径带 %20）

// ✅ 新写法（fileURLToPath 正确解码）
import { fileURLToPath } from 'node:url';
const dir = fileURLToPath(import.meta.url);
// 输出: C:\Users\lcl\AppData\Roaming\DSH Desktop\...
// existsSync → true
```

> 同包 `webui.js` 已正确使用 `fileURLToPath`，证明包内规范本就应如此——screen-watch.js/util.js/core.js 是漏写的 bug。

### 3.3 为何附带问题3/4 长期潜伏
- 安装路径含空格（`C:\Users\lcl\AppData\Roaming\DSH Desktop\`），**必然触发** %20
- 但用户此前未启用 `desktopWatch`（桌面监控），screen-watch.js 的 bug 未被感知
- bot-gateway 数据实际仍在 `bot-gateway/` 目录（可能部分路径走 `process.cwd()` 兜底成功），未造成数据分裂，问题4 仅表现为 WARN 日志
- 同包的 webui.js 用对 fileURLToPath，说明作者知道正确做法但没统一

### 3.4 修复验证
- 3 个文件 `node --check` 语法通过
- 全包 grep `new URL(.*import\.meta\.url)\.pathname` → **0 处残留**
- 端到端实测 `getDshHomeDir()` → 正确返回 `C:\Users\lcl\AppData\Roaming\DSH Desktop\dsh-home`，`sessions` 标志物可探测
- 旧方法对比：`DSH%20Desktop` existsSync=false；新方法：`DSH Desktop` existsSync=true
