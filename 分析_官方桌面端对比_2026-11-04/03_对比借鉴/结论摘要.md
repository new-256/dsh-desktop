# 结论摘要：官方桌面端 vs 我们

**一句话**：官方把「渲染层安全」和「发布工程」做到了工业化水平；我们把「装得上、打得开、坏了自己修」做到了官方根本不需要考虑的深度。官方那套不能照抄（靠自家 monorepo、服务端、EV 证书），但有五样东西是真金。

## 我们强在哪

1. **出事之后的自救**：8 级自愈阶梯 + 三级伤害护栏（不可逆操作必须有正面证据）+ 逐条归因隔离 + 快照自动装回 + 托盘安全模式。官方只有「禁用全部插件然后重启」一个动作——因为它不面对用户自由装插件。
2. **安装可靠性**：vendor 哈希清单（8 分卷逐卷 sha256）、解压前先验、失败隔离重试、junction 安全删除（Electron 会顺着链接删目标，我们实测过）、原子写、迁移备份有上限。
3. **离线与弱网**：默认离线可用；镜像可切；镜像没同步完整依赖时给出可操作提示；GitHub + npm 双源核对，不会提示一个 npm 上还没发的版本。
4. **不装样子的优雅关闭**：实测证明 Windows 上 SIGTERM handler 根本不触发，于是改成「监听真实 exit」，不写假阶梯。

## 我们弱在哪

1. **没有代码签名** → 用户下载后第一件事就是撞 SmartScreen「未知发布者」红屏。这与「总能装得上」直接冲突；而且是资金与流程问题，不是代码问题。
2. **运行期更新不校验哈希** → 构建期我们验 8 个分卷，运行期下载后端包却只查长度。镜像截断或被替换时会静默装上坏树。
3. **插件故障归因靠猜** → 没有「故障前谁装了什么、禁了什么」的结构化记录。三次事故卡在同一处。
4. **安全边界偏松**：两个窗口都是 `sandbox:false`、没有导航白名单、cookie 完全没处理（cookie 不按端口隔离，旧后端的 cookie 会串到新端口）。

## 最值得抄的 5 件事

1. **B-01 清理遗留 cookie**（S）——官方注释直接点明「cookies ignore ports」，而我们随机端口 + 零处理。这是真 bug。
2. **B-02 启动与停止的硬性 deadline**（S）——我们现在有个 async executor 反模式，后端哑火会**永久**停在启动画面。
3. **B-03 更新轮询退避 + 抖动 + 单调时钟**（S）——纯逻辑，弱网下更新提示不再时有时无。
4. **B-04 插件操作历史环形日志**（M）——2×256KiB、单条 4KiB、500ms 排空，附进崩溃报告并标明「context, not proof of cause」。把归因从「猜」变成「读」。
5. **B-17 下载包完整性校验**（S）——registry 元数据里本来就有 integrity，接入成本接近零。

## 但请先做这件事

比以上全部更急的是**隐患 H-04**：profile 隔离的兜底分支走 `rimraf` **直接删用户数据**，与 README「不删任何数据」的承诺相反。改动极小（改成 copy 成功后再删；copy 也失败就放弃本轮隔离），却能消掉一条数据丢失。
