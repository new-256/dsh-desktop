## 0. 先讲形态差异（不讲清就会得出错误结论）

| 项 | 官方 `@deepseek-ai/dsh-desktop` | 本项目 DSH Desktop |
|---|---|---|
| 版本 / 归属 | 0.2.2-alpha.3，官方 monorepo 的 workspace 包 | 0.3.47，第三方独立外壳，**不参与**官方构建体系 |
| 交付对象 | 官方产品的桌面形态（含账号、服务端策略、品牌） | 普通 Windows 用户，「装上就能用」 |
| 与后端的关系 | 拥有子进程 stdio（可发 IPC 关闭指令）、版本强耦合 | 启动标准 `dsh web` CLI，随机端口，后端版本可任选/回退 |
| 页面承载 | 自管 `dsh-app://` 协议（`ipc.ts:114`、`main.ts:787`） | 直接 `loadURL(http://127.0.0.1:随机端口)`（`main.js:1426`） |
| 更新源 | electron-updater + 官方发布渠道（COS）+ 服务端强更策略 | GitHub master + npm 双源核对，**通知制**（不偷跑） |
| 构建 | pnpm workspace + tsc + tsdown bundle + ~200 个 spec | 单包 electron-builder，JS 直出 asar |
| 代码规模 | `src/` 85 个文件 / 593KB + 11 个专用 preload + 189 个测试文件 + 184 个构建脚本 | `main.js` 2,703 行 + `updater-backend.js` 4,577 行（合计 7,280 行，占运行期 JS 约 93%）+ 11 个小模块 |

**判读纪律**：官方做法若依赖其 monorepo 构建体系、`dsh-app://` 协议、官方服务端、账号体系，只能借鉴**抽象与纪律**，不得照搬机制。这类项在「可借鉴性」列标 `仅抽象` / `不适用`。

## 1. 证据与判读规则

- **官方证据**：`src/xxx.ts:行`（对应 `01_官方侦察/upstream/apps/desktop/src/`）。读不到写【未证实】。
- **我方证据**：`文件:行`。仅凭 CHANGELOG 自述不算证据。
- **差距判定**：`领先`（我方更完整/更适配本形态）、`持平`（等价，路线不同）、`落后`（官方明确更优且能落地）、`我方独有`（官方架构上不做，但对我们的用户真有价值）、`不适用`（官方做法在本形态无法成立）。
- **影响面**：给用户可感知的后果（崩溃 / 数据丢失 / 多等 30 秒 / 装不上 / 看不懂），不是技术术语。

## 3. 小结

### 我方明确领先（且是卖点，不能丢）

1. **插件失败的自愈与归因**（维度 6）：阶梯 + 三级伤害护栏 + 解析根模型 + 快照装回 + 插件轮测 + 安全模式。官方在**崩溃恢复路径**只提供一个插件动作（`disablePlugins()`，`fatal-recovery.ts:12`），其 Host 侧是否有更细的插件隔离本次未取得证据【未证实】——所以准确的表述是"我方在归因式逐条隔离上明显更细"，而不是"官方完全没有"。
2. **运维取证的覆盖面**（维度 7）：**双方都有崩溃报告**（我方 0.3.39 就是对齐官方 `crash-report.ts` 做的，`source`/`phase`/10 份保留/256KiB 上界一致），我方多出的是——专用生命周期台账且**明确写出「有 start 无 exit ⇒ 外部强杀」这条判据**（官方把 `started`/`quit-requested` 混在 update-journal 里，未定义推断规则）、份数+天数双上限轮转、桌面报告归并成一份。**注意**：这条判据目前只写进文件、未被生产代码读取消费（隐患 H-11），所以它是"领先的设计"而非"已在生效的能力"。
3. **离线/弱网**（维度 12）：离线默认路径、镜像源可切、镜像未同步时的可操作提示、GitHub+npm 双源核对。
4. **安装成功率的机制建设**（维度 13）：vendor 哈希清单、分卷验签、解压重试、junction 安全删除、原子写、迁移备份上限。
5. **优雅关闭不装样子**（维度 5）：实测证明 Windows 上 SIGTERM handler 不触发，于是改用"监听真实 exit"。

### 官方明确领先（本轮该抄的）

1. **代码签名**（维度 4/15）：这是唯一一条**直接卡住用户第一步**的差距。
2. **更新检查的工程化**（维度 3）：退避 + 抖动 + 单飞 + revision 绑定 + 通道密封。
3. **插件操作历史**（维度 7）：把归因从"猜"变成"读"。
4. **renderer sandbox:true**（维度 1）：零功能损失的加固。
5. **工程化程度**（维度 10/11）：模块划分、类型、CI、文本快照。

### 路线不同但等价

- 页面来源自证：官方 `dsh-app://` 固定源 vs 我方"随机端口 + 窗口身份校验"。
- 更新应用：官方 electron-updater/NSIS vs 我方"暂存 + 重启时无占用替换"。
- journal 形态：官方每启动一个 JSONL（资格取证）vs 我方单文件 30 条滚动（跨重启可追溯）。

### 完全无法对标

- 服务端强更策略、账号/登录、COS 发布流水线、官方插件市场审核、`dsh-app://` 协议体系、11 个 preload 拆分、macOS 公证。
- 这些依赖官方 monorepo / 服务端 / 账号，独立外壳复制即死。

## 4. 影响面排序（只回答"用户会先撞到什么"）

| 排序 | 缺口 | 用户实际感受 |
|---|---|---|

| 3 | 无插件操作历史 | 插件故障后只能靠时间戳反推 → 我们修得慢 → 用户等得久 |
