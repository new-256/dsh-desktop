### 1.1 非 DOM 但同属「外部值 → 解析器」的注入面

| 面 | 0.3.47 | 0.3.48 | 断言 |
|---|---|---|---|
| CSS 选择器拼接 | `document.querySelector('input[name=route][value=' + route + ']')`、`'input[name=ndist][value=' + nd + ']'` —— `route`/`nd` 来自 `settings.npmRegistry`/`settings.nodeDist`（用户可编辑的 settings.json），构造值可让选择器解析异常并中断整个 `renderState` | `pickRadio(ROUTE_RADIO_IDS/NDIST_RADIO_IDS, value)`：`typeof === 'string'` + `hasOwnProperty` 查表，值不参与选择器 | `scripts/test-h06-settings-dom.js` B2/B3；electron「选择器注入」 |
| 内联脚本 | `<script>` 内联在 HTML 中被 CSP `unsafe-inline` 放行 | 无内联脚本；`script-src 'self'`，运行时注入的内联 `<script>` 与 `eval` 均被 CSP 拦截 | electron「CSP 阳性对照」两项 |
| 事件属性 | HTML 内无 `on*=` | 无 `on*=`（A4）；DOM 侧一律 `addEventListener` | test-h06-settings-dom A4 |
| 样式属性 | 表格里 `style="width:26px"` 内联 | `.col-check { width: 26px; }` 类（`settings.html:49`） | test-h06-settings-dom A5（无 `innerHTML`）/ 手工核对 |

## 2. 桥面（`settings-preload.js`）收敛

| 项 | 0.3.47 | 0.3.48 |
|---|---|---|
| 通道登记 | 20 个方法各自 `ipcRenderer.invoke('字面量')` | 统一 `invoke(channel)`，channel 必须命中 `ALLOWED_CHANNELS`（22 条），未登记即**抛错** |
| 通用能力 | 无（但新增方法无门槛） | 不暴露通用 `invoke`/`send`；`ipcRenderer.invoke` 只出现 1 次（helper 内） |
| 入参 | 直接透传 | `asText` / `asOptionalText` / `asArray` 类型收敛（业务校验仍在主进程） |
| 监听回调 | `catch {}` 静默吞 | `catch` 后 `console.error` → 主进程 `console-message` 钩子写进诊断日志 |

高风险通道（本窗口持有）：`plugins:install`、`plugins:import-legacy`（二者都会执行包的
`postinstall` = 代码执行）、`backend:rollback-to`、`plugins:set-path-entry`、`plugins:set-dsh-home-env`、
`shell:copy-text`。修复后前两者在渲染层多一道 `window.confirm`（展示确切包名/清单）。

## 3. 主进程侧 sender 校验现状（只读核查，不属于本任务写入域）

`main.js` 自 0.3.42 起所有通道统一经 `handleIpc()` → `assertOwnedSender()`：
sender 必须是 `mainWindow` / `settingsWindow` 的 `webContents`，且 origin 必须是 `file:`
或本机回环。核查结果：本任务涉及的 **22 条通道全部经 `handleIpc` 注册**，主进程内
**0 处裸 `ipcMain.handle`**（测试 C5/C6/C7 断言）。因此 H-06 的第 3 条要求
（「若主进程侧没有 sender 校验则记录并告知 lead」）结论为：**已具备，无需跨域修改**。

补充风险（记录，非本任务修改）：`assertOwnedSender` 只区分「是否本应用窗口」，不区分
「是主窗还是设置窗」—— 设置窗与主窗共享同一套通道权限。若后续要按窗口分级，
需在 `main.js` 侧增加 per-channel 窗口白名单（属 main.js 写入域）。
