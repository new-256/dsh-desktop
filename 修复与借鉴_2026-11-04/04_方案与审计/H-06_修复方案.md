# H-06 修复方案：设置窗脚本注入与提权链

> 版本 0.3.48 · 任务 task-7 · 写入域：`settings.html`、`settings-preload.js`、新增 `settings-renderer.js`
> 隐患出处：`分析_官方桌面端对比_2026-11-04/02_本地盘点/隐患清单.md` H-06（P1）
> 验收依据：`04_方案与审计/H06_注入路径自检清单.md`（28 个汇点，漏一处即失败）

## 1. 问题本质

不是「某一行忘了转义」，而是**两个缺陷叠成一条提权链**：

```
插件名（外部可控 JSON 字段）
   → settings.html 用 innerHTML 拼进表格
   → 名字里的 <img onerror> 在该窗口执行
   → 该窗口的 settings-preload.js 暴露 plugins:install
   → dsh plugin add <spec> → pnpm → 包的 postinstall 执行
   = 代码执行
```

其中第二环（`script-src 'unsafe-inline'`）让注入不需要任何绕过技巧：内联事件处理器
天然可执行。所以只做「转义」不够 —— **必须同时收掉内联脚本许可**，否则任何一次
新增的 `innerHTML` 都会立刻重新打开这条链。

外部字符串的来源链（0.3.47 实测）：
- 插件名 = profile `package.json` 的 `dsh.profile.bundles` / `dependencies` 键（`updater-backend.js` 原样 `String(name)`）；
- `reason` / `nodeEngine` / `installed.version` = 插件 manifest 字段与日志文本；
- 旧 Home 路径与孤儿插件名 = 用户磁盘上的目录名（本地目录名可被构造）。

## 3. 修复方案（四件事，逐条对应验收）

### 3.1 脚本外提（取消内联许可的前提）

- 新增 `settings-renderer.js`（476 行 / 24,678 B），内容 = 原内联脚本的**行为等价重写**；
- `settings.html` 只剩一行引用：`<script src="settings-renderer.js"></script>`；
- 打包：`package.json` 的 `build.files` 由出包团队维护 —— 当前已是 `"*.js"` 通配
  （`scripts/build-files-gate.js` 门禁通过，见审计文档 §4），**若将来改回逐个点名，必须补上
  `settings-renderer.js`，否则设置窗白屏**；
- 脚本首行设置 `documentElement.dataset.rendererLoaded = '1'`，作为「CSP 是否真的放行了
  同源脚本」的真机探针（真机测试的判据，不做静默降级）。

### 3.2 CSP 收紧（一刀切掉内联脚本与内联执行）

```
default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:
```

- `default-src 'none'`：本窗口不需要任何网络/字体/媒体能力（纯本地设置页），全禁最省心；
- `script-src 'self'`：只允许同目录脚本文件，**无 `'unsafe-inline'`、无 `'unsafe-eval'`**；
- `style-src 'self' 'unsafe-inline'`：本页有 `<style>` 块（保留，符合任务书要求）；
- `img-src 'self' data:`：图标位不用网络图，`data:` 供未来内联小图标。
- 顺带把唯一的 `style="width:26px"` 内联样式改为类 `.col-check`（`settings.html:49`）。

### 3.3 全部动态内容改走 DOM API（消灭 `innerHTML`）

`settings-renderer.js` 内置一套最小工具，外部字符串**只能**从这三个口进 DOM：

| 工具 | 作用 | 关键点 |
|---|---|---|
| `el(tag, className, text)` | 建元素并写文本 | 文本一律 `textContent`，永不解析 HTML |
| `option(value, label)` | 建 `<option>` | value/label 分别赋值，不拼字符串 |
| `buildTable(headers, rows)` | 建表 | 单元格是**节点数组**，调用方只能给节点 |
| `clear(node)` | 清空容器 | `replaceChildren()` 取代 `innerHTML = ''` |

被重写的高风险位置（对照清单 §1 的 #13、#18、#19、#27）：兼容性表、旧 Home 表、导入
结果表、两处版本 `<option>`。勾选框改用 `cb.dataset.i = String(i)`，导入时按
`legacyScan.orphans[Number(cb.dataset.i)]` 取值（与原 `data-i` 机制一致）。

**选择器注入**一并封掉：`route` / `nodeDist` 只做白名单查表

```js
const ROUTE_RADIO_IDS = Object.freeze({ mirror: 'r-mirror', official: 'r-official' });
function pickRadio(map, value) {
  if (typeof value !== 'string' || !Object.prototype.hasOwnProperty.call(map, value)) return null;
  return $(map[value]);
}
```

`value = 'mirror"] , body *:not(x)'` 只会查不到（返回 null），不再抛选择器解析异常把
整个 `renderState` 打断。

### 3.4 桥面收敛 + 高权限动作显式确认

`settings-preload.js`（130 行）：

1. **通道白名单**：`ALLOWED_CHANNELS`（22 条）→ `invoke(channel, ...args)` 命中校验，
   未登记**直接抛错**（开发期禁静默兜底：加通道忘登记当场炸，而不是运行时才 404）；
2. **不暴露通用 `invoke/send`**：渲染层无法自行编造通道名；
3. **入参类型收敛**：`asText` / `asOptionalText` / `asArray`（只挡类型，业务校验仍在主进程）；
4. `onPluginLog` 的回调抛错不再 `catch {}`，改为 `console.error`（主进程 `console-message`
   钩子会写进诊断日志，属"可见降级"而非静默吞）；
5. 渲染层对 `plugins:install` 与 `plugins:import-legacy` 增加 `window.confirm`，把确切
   包名/清单摆给用户 —— 这是本窗口唯一的「代码执行」入口。

### 3.5 主进程侧 sender 校验（只读核查，不改 main.js）

结论：**已具备**。`main.js` 自 0.3.42 起所有通道经 `handleIpc()` → `assertOwnedSender()`
（sender ∈ {mainWindow, settingsWindow}.webContents，且 origin ∈ {file:, http(s) 本机回环}）。
本任务涉及的 22 条通道全部经 `handleIpc` 注册，主进程内 0 处旁路裸注册
（`scripts/test-h06-settings-dom.js` C5/C6/C7 断言）。

记录一条**不在本任务写入域**的残留风险：`assertOwnedSender` 只判定「是否本应用窗口」，
不区分主窗/设置窗 —— 两个窗口共用同一套通道权限。若要分级，需在 `main.js` 侧加
per-channel 窗口白名单（属 main.js 团队）。

## 4. 不变式（改这些代码时不得破坏）

1. `settings.html` 里**不得**出现内联 `<script>`、`on*=` 属性、`style=` 内联样式；
2. `settings-renderer.js` 的可执行代码里不得出现 `innerHTML` / `outerHTML` /
   `insertAdjacentHTML` / `document.write` / `eval` / `new Function`；
3. 外部值不得进入 CSS 选择器（只能查表）；
4. 桥面新增方法必须同时登记 `ALLOWED_CHANNELS`；
5. 新增任何「外部字符串 → DOM」位置，必须先在 `H06_注入路径自检清单.md` 登记 id。

## 5. 风险与取舍

| 取舍 | 说明 |
|---|---|
| `window.confirm` 是浏览器模态框 | 与主进程 `dialog` 相比样式朴素，但**零新增 IPC**、零新增权限；且确认文案直接展示用户输入的确切包名，比改成主进程对话框更难被诱导点击 |
| `style-src` 仍留 `'unsafe-inline'` | 任务书指定的目标串；本页样式全为静态 `<style>` 块，没有用户可控的样式内容（已改为类，无内联 style 属性） |
| `default-src 'none'` | 本窗口无任何网络需求；若将来要加载远程资源，必须显式开 `connect-src`/`img-src`，而不是放宽 `default-src` |
| 兼容性表语义 | 逐节点构造与整表拼接的**可见结果一致**（真机断言行数、文本、勾选态），唯一差异是 `innerHTML` 时代的"错误数据会变成 DOM"，现在只会是文本 |

`window.__xss` 未被置位、payload 只以文本出现；并用阳性对照证明 CSP 真的拦得住运行时
注入的内联脚本与 `eval`。实测输出见 `H-06_H-10_审计.md` §2。
