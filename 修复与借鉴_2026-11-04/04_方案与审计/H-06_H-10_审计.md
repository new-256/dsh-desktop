#### 根因

`test-047` 的契约是**同步可读**：`diag.write('模拟错误：error something failed')` 返回后立即断言
「桌面上有那份固定名报告」。第一版 H-10 把这条记录也放进了 200ms 队列 —— 断言时报告还没被
创建（后续「上一轮报告归档」也因此连锁失败，因为压根没产出可归档的那份）。

对照 0.3.47：错误行会**同步**写错误清单 + 桌面报告（`settings.html:221-223` 时代的
`statSync`+`appendFileSync`）。也就是说这是我引入的**回归**，不是既有缺陷、也不是测试过时。
关键产物的契约（桌面报告纪律 + `crash-report.js`「报告文件名 1s 内可被引用」）要求它在
写入返回时就存在。

#### 修复（机制化分层，未改测试、未加 sleep、未放宽断言）

`diag-log.js` 现在按**记录的去向**（不是文件名）分两层：

```js
function feedsCriticalSink(record) { return record.isError === true; }   // 命中 ERROR_LINE_RE
...
if (forceDurable || feedsCriticalSink(record)) {
  flushSync(FLUSH_BUDGET_MS);   // 屏障：先把更早的高频行落盘（保顺序）
  writeBatch([record]);         // 直写：不进队列，不受队列上限/丢弃计数影响
} else {
  queuePush(record);            // 高频行：继续 200ms 批量
  scheduleFlush();
}
```

- **自动 durable**：命中错误关键字的记录必然写进「错误清单 + 桌面错误报告」两个关键产物
  → 返回前落盘；
- **显式 durable**：新增导出 `writeDurable(...)`，给迁移/隔离/更新决策等**将来新增**的关键
  产物用 —— 判据不写死任何文件名；
