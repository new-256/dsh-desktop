## A. 安全与隐私（建议优先，因涉及公开仓库与用户反馈流程）

### S-1 桌面日志未脱敏，泄露本次会话的 Web 鉴权 token ★★★
- **证据（生产环境实测）**：`C:\Program Files\DSH Desktop\logs\DSH-Desktop-日志.txt`
  `后端输出 dsh web: http://127.0.0.1:63742/?token=<redacted>`
  `步骤5 后端已启动: http://127.0.0.1:63742/?token=YhkK…`（错误清单同样收录）
- **为什么重要**：README 明确让用户"把日志发过来定位问题"——用户按文档操作就会把当时 token 一起发出去。token 随进程退出失效（实际风险低），但"日志里有完整凭据"本身不该存在。
- **建议**：`diag-log.js` 写入前统一脱敏 `token=([A-Za-z0-9_\-\.]{8,})` → `token=<redacted>`；同时覆盖崩溃报告与错误清单；补一条单测断言"日志中不得出现 16 位以上 token 值"。
- **工作量**：S

### S-2 公开仓库历史含一次性 token 与本机用户名路径 ★★
- **现状**：已对**当前版本**脱敏并加提交前扫描门禁；但历史提交 `c8f6ffe`/`348e5a8`/`b881f67` 里仍保留原始值。
- **建议**：如需彻底抹除，用 `git filter-repo` + `git push --force-with-lease`（需明确授权；单用户仓库风险可控）。否则登记为已接受风险。
- **工作量**：S（但属破坏性操作，需你点头）

### S-3 缺 integrity 元数据时默认放行 ★★
- **证据**：`updater-backend.js` B-17 实现——`dist.integrity`/`shasum` 缺失时 `ok:false` + `missingMetadata`，但默认 `accept-unverified` 继续安装，只有 `DSH_REQUIRE_INTEGRITY=1` 才拒绝。
- **影响**：实现了校验，但"没有校验信息"这条路径仍是**放行**，与你"禁止自动降级/兜底"的规则精神冲突。
- **建议**：默认改为拒绝（fail-closed），把放行改成显式开关 `DSH_ALLOW_UNVERIFIED_INSTALL=1`。
- **工作量**：S

### S-4 设置窗 CSP 收紧后的第三方插件兼容性未实测 ★★
- **证据**：`settings.html` CSP 现为 `default-src 'none'; script-src 'self'`；若有第三方插件往设置窗注入内联脚本/远程脚本，会被静默拦掉。
- **建议**：拿 3~5 个常用第三方插件（kexi、cli-bridge、workbuddy-auth 等）各开一次设置面板，看控制台是否有 CSP 拒绝；把结论写进 CHANGELOG 的"已知限制"。
- **工作量**：S

### S-5 未签名 / 无差分更新包（资金与流程问题） ★★
- **证据**：`package.json` 无 `certificate*`、无 `differentialPackage`；四版安装包均 `NotSigned`，240MB 全量。
- **影响**：用户首装撞 SmartScreen「未知发布者」；每次更新下载 240MB。
- **建议**：代码签名走流程（EV/OV 证书）；差分更新在拿到签名后再评估（官方用 electron-builder `differentialPackage`）。
- **工作量**：L（依赖外部）

## E. 依赖与构建一致性

### D-1 Node 版本三处不一致 ★★
- **证据**：`backend/versions.json` + `backend/node.exe` = **v24.21.0**（运行期被我们的更新器升级过）；`build/cache/node-v24.4.0-win-x64.zip` = **24.4.0**（出厂 seed 缓存，34.5MB）；安装日志里还出现 `更新检查完成 {"updates":["node→24.22.2"]}`。
- **影响**：出厂 seed、活跃运行时、可用更新三个版本并存，排查"ABI 不对"类问题时会误导。
- **建议**：明确"seed 版本 = 打包时锁定版本"，把 `build/cache` 纳入打包脚本的版本校验（与 `package.json` 的 `DSH_NODE_MAJOR`/固定版本对齐），并在日志里打印三者版本。
- **工作量**：S

### D-2 安装器版本选择页硬编码远古版本 ★
- **证据**：`build/installer.nsh:23-24`
  `${NSD_CB_AddString} $DshBackendVersionCombo "0.1.5-alpha.2"`、`"0.1.5-alpha.1"`
- **影响**：首次安装页给用户可选 0.1.5 系列（早已过时），且与我们当前 0.2.2-alpha.3 差了一个大版本；选错会装出很旧的后端。
- **建议**：改为从 `versions.json`/vendor 清单动态取值，或直接删掉这两个硬编码项。
- **工作量**：S

### D-3 `build/cache` 里 34.5MB 陈旧 zip ★
- **证据**：`build/cache/node-v24.4.0-win-x64.zip`（构建缓存，未入仓库、未入安装包）。
- **建议**：清理或纳入 `.gitignore`（已忽略）；确认打包脚本不会误用它作为 seed。
- **工作量**：S
