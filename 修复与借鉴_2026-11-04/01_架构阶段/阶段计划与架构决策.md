## 2. 写入域划分（防冲突）

两个巨型单文件（`main.js` 2.7k 行、`updater-backend.js` 4.6k 行）是共用热点。按**文件所有权**而非功能切分：

| 阶段 | 写入域 | 所有者 |
|---|---|---|
| 一 | `updater-backend.js` | 更新后端团队（H-04/H-05） |
| 一 | `main.js` + `startup-deadline.js` | 主进程团队（H-01/H-02/H-03/H-08） |
| 一 | `settings.html`/`settings-preload.js`/`diag-log.js` | 渲染与日志团队（H-06/H-10） |
| 一/二 | `package.json`(version)/`CHANGELOG.md`/`release/` | 出包团队（唯一 bump 权） |
| 二 | `main.js` + `url-policy.js` + `session-hygiene.js` | 主进程团队（B-05/B-01/B-11 + 阶段一遗留接线） |
| 二 | `updater-backend.js` + `update-schedule.js` | 更新后端团队（B-03/B-17/B-08/B-06） |
| 二 | `plugin-journal.js` + `crash-report.js` | 渲染与日志团队（B-04） |

跨域协作靠**书面接口契约**而非互相改文件：`plugin-journal` 的 `record(entry)` 契约与「main.js 接线点清单」由模块方产出、接线方照抄（见 `04_方案与审计/plugin_journal_main接线点清单.md`）。

## 3. 关键架构决策

1. **新逻辑一律落新文件，禁止继续膨胀 `main.js`/`updater-backend.js`**。本轮新增 7 个根级模块：`app-identity.js`、`startup-deadline.js`、`settings-renderer.js`、`url-policy.js`、`session-hygiene.js`、`update-schedule.js`、`plugin-journal.js`；两个巨型文件只做接线。
2. **不照搬官方 `dsh-app://` 协议反代**：它需要「一次性 URL 换 cookie」与「注入清单」两项 Host 侧配合（侦察标注未证实），硬上等于自建反代层，风险净增。只借其**安全结论**（渲染层不接触后端端口语义 → 我们用 sandbox + 导航白名单 + 开窗默认拒达成等效收益）。
3. **不照搬 `ELECTRON_RUN_AS_NODE`**：实测 Electron 内置 Node `modules=149` vs 独立 node `137`，后端 12 个 native 模块按 137 预编译，迁移会全崩。
4. **门禁优先于人工核对**：凡是「只有打包/成品才暴露」的缺陷类型，一律做成 `npm run dist` 前置门禁（引用闭包、appId 一致性、剥离字段检查、产物守卫），并要求「红→绿两次快照 + 故意制造红来证明门禁有效」。
5. **durability 分层而非全同步**：高频日志行批量写（200ms），关键产物（错误清单/桌面报告/迁移隔离/更新决策）走 `writeDurable` 返回前落盘；判据是机制（`record.isError`/显式 durable 标记），不是文件名名单。
6. **测试不许编码缺陷、也不许为通过而放宽**：`test-043` 里「profiles 整树删除点存在」的断言正是 H-04 缺陷本身，已翻转为反向断言；`test-047` 4 项红被判定为产品回归并修产品（测试文件一字节未改）。

## 4. 验证策略

- 每项修复必须给**失败路径**证据（真实占用句柄造 EPERM、icacls 造读失败、半截 JSON 造损坏标记、篡改 1 字节造校验失败），不接受只跑 happy path。
- 时间相关测试用**假时钟**推进，禁止真等 600s。
- 每个测试进程 300s 超时，超时 kill 进程树并输出卡点与最后 50 行。
- 测试与运行期间同步启动资源监控（CPU/内存/GPU/显存 2s 采样），GPU 可用时不降级 CPU。
