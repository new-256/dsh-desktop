## 1. 产品回归 vs 旧契约：判定依据

- **产品回归**：仓库源码的行为变了导致断言失败，且断言描述的是**仍然有效的产品契约** → 必须修产品。
  - 例：`test-047` 断言"桌面错误报告应为固定名且当场存在"，H-10 批量化后关键产物延迟落盘 → 契约仍有效、实现退化 → 修产品（diag-log 分层 durability）。
- **测试编码旧契约**：断言固化了**已被替换掉的实现选择**（不是产品承诺） → 退役或重写测试。
  - 例：`test-packaging` 的 `covered()` 只认精确文件名与 `dir/**/*`；`build.files` 改成 `*.js` 通配后必然全红，而"文件是否进包"这个真契约并没有被破坏。
- **门禁自身缺陷**：门禁把"调用方式错/自身匹配器错"当成产品红 → 修门禁，并在门禁里加自测防退化。

## 3. 门禁集合（当前事实，全部串进 `npm run dist`）

```
dist-artifact-guard pre
  → build-files-gate（引用闭包 vs 白名单 + 裸包 + 剥离字段，默认 strict）
  → app-identity-gate（随包 appId 常量一致性 + 门禁自测）
  → pack-vendor
  → electron-builder --win
  → dist-artifact-guard post（校验"确实是本轮新产物"）
```

- 逃生阀：`node scripts/build-files-gate.js --no-strict` 会打印
  「⚠⚠ 已跳过严格模式（--no-strict）：【3b】…只告警、不阻断。这是已知风险状态…请在交付清单里如实记录本次绕过」。
- `dist-artifact-guard pre` 会把同版本旧产物先挪到 `release/_stale/`，因此**任何一环失败都不会留下"看起来是新的"旧文件**；`post` 再用 mtime/体积/SHA-256 三重确认产物是本轮新生成的。
- 编译门禁（`stage1-compile-gate.js`）额外把上面两道打包门禁作为【第零节】【第零·二节】纳入同一次体检，避免"门禁没跑"这种沉默失败。
