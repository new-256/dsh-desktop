## 2. 事故记录：`settings.html` 被辅助命令截断（已恢复）

### 2.1 现象

改造 CSP 时用一条 Node 单行命令做「删内联脚本块」的文本变换，命令用
`text.indexOf('<script>')` 找起点、`text.lastIndexOf('</script>')` 找终点。因为我刚在
头部注释里写了 **`不使用任何内联 <script>/on* 属性`** 这句说明，`indexOf` 命中的是
**注释里的 `<script>`**，于是 `before` 只到注释处、`after` 从真正的 `</script>` 之后开始，
中间 1.1 万字节正文被整段丢弃。

### 2.2 报错与当时状态（全文）

```
(node -e 命令退出码 0，无报错 —— 这是最危险的地方：命令"成功"了)
剩余 <script occurrences: 1
```

随后 `read settings.html` 显示文件只剩 **10 行 / 526 字节**：

```
1: <!DOCTYPE html>
2: <html lang="zh-CN">
3: <head>
4: <meta charset="utf-8">
5: <!-- 0.3.48 · H-06：默认全禁 + 脚本只允许同源文件（不再 script-src unsafe-inline）。
6:      内联脚本已外提为 settings-renderer.js —— 该文件必须进 package.json 的 build.files。
7:      'unsafe-inline' 仅保留给 style（本页有 style 块），页面内不存在内联 <!-- 0.3.48 · H-06：脚本外提（CSP 只允许同源文件，不再有内联脚本） -->
```

（第 7 行可见注释与脚本标签被错位拼接 —— 典型的"定位锚点被自己的注释污染"。）

2. 搜索同版本副本：`settings.html.with-mobile.bak`（2026-09-10，含手机端代码，版本不对，弃用）；
3. 发现打包产物 `release/win-unpacked/resources/app.asar`（2026-10-20）：
   `@electron/asar` 解出的 `settings.html` = **28,552 字节**，与截断前工作区文件字节数**完全一致**，
   且校验一致：`<script>` 内联标签 1 个、`mobile` 命中 0、`innerHTML` 命中 10、
   `dshSettings` 命中 1 —— 与原文件逐项吻合；
4. 取回后写入 `.tmp-h06-h10/settings.asar.html`，用 `read` 工具逐段核对（第 1-8 行、
   第 155-176 行等关键段落与截断前读到的一致）；

### 2.4 根因与纪律（已加入本阶段经验）

- 根因不是"文件坏了"，而是**定位锚点用了会被自己改动影响的最短字面量**，且变换脚本

  结构断言；③ 断言失败不落盘。

### 3.6 真缺陷：`app.exit()` 不触发 `exit` 事件 → 队列全丢（已修复）

这是本轮**唯一一个靠"单测全绿"发现不了、只有真机集成冒烟才暴露**的缺陷。

#### 现象（首轮冒烟，未修复时）

冒烟脚本在真实 Electron 主进程里 require 新 `diag-log.js`，写 3 行（header + 2 条），
**故意不手动 flush**，直接 `app.exit(0)`：

```
{"queuedBeforeExit":3,"existsBeforeExit":{"log":false,"err":false,"report":false}}
--- 落盘主日志 ---
主日志缺失
--- 错误清单 ---
错误清单缺失
--- 桌面报告 ---
桌面报告缺失
[EXIT=0]
```

进程"干净退出"（exit code 0）、没有任何报错、`node --check` 通过、H-10 的四阶段测试全绿
（因为它们在纯 Node 里跑，`process.exit` 会触发 `exit`），**但真实 Electron 退出时日志一行都没落盘**。

#### 根因

`process.once('exit')` 是纯 Node 语义。Electron 的 `app.exit(code)` 文档明确："立即退出，
不触发 `before-quit` / `will-quit`"，且实测连 Node 的 `process 'exit'` 事件也不走
（Chromium 直接结束进程）。而 `main.js` 里 `app.exit(0)` 出现在最关键路径上：

```
main.js:50    app.exit(1)                       启动失败
main.js:2643  app.relaunch(...) + app.exit(0)   更新后重启（每次更新必走）
main.js:819/883/928/3061  app.exit(0)           启动预检弹窗选择「退出」
main.js:1399/2083/2814/3237/3276  app.quit()    正常退出
```

也就是说：**用户点「重启并更新」的那一刻，恰恰是日志最可能全丢的时刻**。

#### 修复

`installExitHooks()` 装四路口（任一触发即 flush，多实例幂等）：

```js
process.on('exit', runAll);                                  // ① 纯 Node / 正常收尾
electronApp.exit = (code) => { runAll(); return raw(code); }; // ② app.exit（唯一可靠口）
electronApp.on('will-quit', runAll);                          // ③ 正常 app.quit
process.exit = (code) => { runAll(); return raw(code); };     // ④ 其他模块直接调用
```

幂等实现：钩子集合挂在 `Symbol.for('dsh.diag.flushHooks')` 上，重复 require（测试里每阶段
一套干净模块）只安装一次包装器，各实例把自己的 `flushSync` 注册进集合。

#### 复验

同一冒烟脚本 → 主日志 3 行（含 `===== 会话开始 PID=… 版本=44.3.0 …`）、错误清单 1 行、
桌面报告（固定名）头 + 1 行，全部落盘；`electron.app.getVersion()` 也正确取到 `44.3.0`。
终验把这条冒烟固化为验证套件的第 5 步（`03_调试阶段/H06_H10_验证运行输出.txt` §5）。

#### 纪律沉淀

- **单元测试全绿 ≠ 集成没问题**：凡是"依赖宿主生命周期"的能力（退出、崩溃、托盘、窗口销毁），
  必须在真实 Electron 里做一次冒烟；
- 断言要看**磁盘上的实际内容**，不能只看退出码（首轮 `EXIT=0` 时磁盘是空的）；
- Electron 官方文档里"不触发 quit 事件"这种一句话，落在我们代码里就是"日志全丢"，
  必须当成真实缺陷修，不能当成"可接受的取舍"。

### 3.7 回归：批量化把「关键产物」也延后了（lead 退回，已修）

#### 现象

```
node scripts/test-047-desktop-report.js
  ✗ 本次启动后：桌面只剩一份报告
  ✗ 桌面报告改为固定名（不带时间戳）
  ✗ 上一轮的固定名报告已归档（带时间戳）
  ✗ 第二次启动出错后：桌面又只有一份
断言 15 项，失败 4 项   → exit=1
```

HEAD 基线同测试 15/15 绿 —— 所以我引入的是**回归**，不是既有缺陷、不是测试过时。

#### 根因（一次"一刀切批量化"的设计错误）

第一版 H-10 把**所有**写入都塞进 200ms 队列，包括「桌面错误报告」。而 `test-047` 的契约是
同步可读：`diag.write('模拟错误：error something failed')` 返回后立刻断言桌面上已有那份固定名
报告。断言执行时记录还在内存队列里 —— 报告不存在，后续「上一轮报告归档」也跟着连锁失败。

对照 0.3.47：错误行本来就是**同步**写错误清单 + 桌面报告。我把关键产物也批量化了 →
`crash-report.js` 那条「报告文件名 1s 内必须可被对话框/用户引用」的契约被破坏。

**判断错在哪**：我当时把 H-10 的诉求理解成"所有写都要快"，实际诉求是"**高频流水**要快"。
关键产物的价值不在吞吐，而在**返回即可读**。

#### 修复（机制化分层，不改测试/不加 sleep/不放宽断言）

```js
function feedsCriticalSink(record) { return record.isError === true; }  // 去向：进错误清单+桌面报告
...
if (forceDurable || feedsCriticalSink(record)) {
  flushSync(FLUSH_BUDGET_MS);   // 屏障：先落更早的高频行，保顺序
  writeBatch([record]);         // 直写：不进队列，不受上限/丢弃影响
} else {
  queuePush(record); scheduleFlush();   // 高频行照旧批量
}
```

另加导出 `writeDurable(...)`，给将来新增的关键产物（迁移/隔离/更新决策）显式声明 ——
判据里**没有**任何产物文件名，也没有测试名。

|---|---|
| `test-047-desktop-report.js` | **15/15 绿**（修复前 4 红） |
| `test-h10-log-throughput.js` | 20/20 绿；5 万行注入期仍 **0 次系统调用**、2.0~3.1µs/行 |
| `test-h10-electron-exit-flush.js` | **12/12 绿**（批量层退出 flush + 真机 durability 层即时落盘） |

#### 纪律沉淀

- **批量化的判据是"谁在读、什么时候读"，不是"写得多不多"**：返回后 1s 内会有人按文件名去
  读的产物，必须 durable；
- 回归测试是契约的载体：`test-047` 里那句"写完之后立刻断言桌面只剩一份"就是 0.3.47 的
  用户可见承诺，任何性能改造都必须先满足它；
- 修回归的正确方向是**补一层语义**，不是把性能收益整体回退（回退会让 H-10 白修）。
