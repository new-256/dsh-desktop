## 1. U-02 关到托盘

**做**：隔离副本启动 → 等首帧 HTTP 200 → 用 `WM_CLOSE` 发给**当场重新取得**的主窗口句柄（不是缓存句柄），校验 `PostMessage` 返回值 → 等 7 s → 断言。

| 断言 | 结果 | 证据 |
|---|---|---|
| ① 进程仍存活 | ✔ | `主进程存活=True`（pid 未消失） |
| ② 主窗口已隐藏 | ✔ | `仍有可见主窗口=0` |
| ③ 托盘图标存在 | ✔ | 溢出区 UIA 找到 `DSH Desktop` 图标元素（supp2/supp5）；supp6 该次枚举抖动未取到（见 §5 诚实边界） |
| ④ 日志有留托盘/通知记录 | ✔ | `托盘气泡已由系统确认显示（balloon-show 已触发）` |

**同时确认了"首次点 X 先弹确认框"这条设计路径**：
- supp2（关窗发生在气泡之前）：`WM_CLOSE` 后窗口**保持可见** 20 s —— 因为 0.3.39 起首次关闭会 `dialog.showMessageBox`（`main.js` 的 `close` 处理：`buttons: ['确认最小化到托盘','取消']`，`preventDefault()`），用户不点确认就**不隐藏**（旧版"弹窗失败也偷偷隐藏"的坑已在 0.3.44 修掉，现在窗口消失必须是用户明确确认的结果）。
- supp5/supp6（气泡已发过 → 进程内 `trayHintShown` 已置位）：同样 `WM_CLOSE`，窗口直接隐藏、不再打扰。

**结论：通过**。两条路径（首次确认 / 后续静默）都符合设计；本次自动化未成功点到确认框按钮（弹框是原生 MessageBox，UIA 未在本机枚举到其按钮），所以"点确认后隐藏"这条路径的证据来自"静默路径"与源代码语义，**未宣称已实测点击**。

## 4. U-08 从托盘点开设置窗

**做**：枚举托盘图标元素 → 列出其支持的 UIA pattern → 依次尝试 `LegacyIAccessible.DoDefaultAction` / `InvokePattern.Invoke` → 检查是否出现托盘菜单窗口（`#32768`）→ 若出现则 Invoke「设置…」。

**结果：未验证（需人工一步）**，精确原因分三层：

1. **枚举抖动**：Win11 的溢出区是 `TopLevelWindowForOverflowXamlIsland`（**no-activate** 浮层）。必须先点任务栏 `∧` 把它展开，`DSH Desktop` 图标元素才会出现在 UIA 树里；同一轮里 U-02 段落能找到、U-08 段落连续两次没找到（supp3/supp4/supp6 均为 `UIA 未枚举到 DSH 托盘图标`）。
2. **模式缺失**：即使拿到图标元素，`TryGetCurrentPattern` 返回的**支持模式列表为空**（`托盘图标支持的模式：` 后无内容）—— 既没有 `InvokePattern` 也没有 `LegacyIAccessiblePattern`，所以 `Invoke()`/`DoDefaultAction()` 无从调用。
3. **菜单不出现**：合成右键（`SetCursorPos` + `mouse_event`）在该浮层上不产生 Electron 的托盘菜单窗口（`EnumWindows` 里没有 class `#32768`），因此也点不到「设置…」。

> 顺带修掉一个**工具自身**的缺陷：pwsh 7 的 `UIAutomationClient` 里**没有** `LegacyIAccessiblePattern` 类型（.NET Framework 才有），早期版本在构造 pattern 映射表时整体抛异常，把 U-08 误判成 `FAIL`。现在每个类型单独 `try/catch`，并把"支持模式列表"如实打印出来 —— 这是"工具缺能力"，不是"产品点不开"。

**替代验证（不是等价替代，是补充）**：设置窗本身已用 **成品 asar + 真 Electron + `sandbox:true`** 在 1179px 与 900px 两档宽度下真实加载并截图，12 项断言全绿（含 `settings:get` / `set-route` 读写往返）。**但"从托盘点开"这个动作本身仍未验证**，需要人工一步。

### 5.1.3 纪律沉淀：门禁阈值必须能解释成缺陷类型，禁止魔法数字

**反例（本次）**：旧门禁写着 `字节数 > 51200`。这个数字与"证据是否可用"**没有因果关系** ——
我们要防的三件事分别是「截到别的窗口」（由 `captureMethod` 覆盖）、「白屏/纯色占位」（由像素统计覆盖）、「写盘截断」（由 magic + 尺寸 + 截断下限覆盖）。而一个**空工作区首页**白底占 79.5%，PNG 压出来天然只有 49 KB；把阈值定在 50 KB，惩罚的是"界面简单"，不是"证据有问题"，换成深色主题或另一个页面立刻误报，反过来也可能放过一张 60 KB 的垃圾图。

**现在的分工**（每条都能翻译成一种缺陷）：

| 断言 | 它防的缺陷 |
|---|---|
| PNG 存在 | 有 json 没图 / 有图没 json |
| 字节数 ≥ **8192** | 写盘写了一半、0 字节、几 KB 占位（**仅此**） |
| magic 正确 | 不是 PNG / 截断到认不出 |
| 尺寸对 viewport | 抓到别的 target、别的 DPR |
| captureMethod 合规 | 全桌面截屏抓到前台别人的窗口 |
| consoleErrors 空 | 页面带着报错被当正常首帧 |
| failedAssertions 空 | 采集时自己声明的断言不达标还入库 |
| **domProbe 锚点** | 这张图不是我们的 UI（空白页/错误页/别人的页面） |
| 像素非空白 | 白屏 / 黑屏 / 纯色占位 |
| domProbe.errorish 空 | 错误浮层被当正常 |

**规则**：新增门禁阈值时，必须写清「这个数对应哪一种缺陷、为什么是这个数量级」；写不出来的阈值不许进流水线。
