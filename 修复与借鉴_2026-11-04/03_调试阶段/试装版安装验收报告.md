## 0. 为什么用试装版（问题本身）

生产安装器 `build/installer.nsh` 的 `DshTerminateAll` 在安装段起点执行：

```
nsExec::Exec 'taskkill /F /T /IM "DSH Desktop.exe"'      # 3 条清扫命令之一
```

而被验收的这台机器上，**被测外壳正是承载 agent 会话的宿主进程** —— 跑生产安装器会把验收会话连同它的后端一起杀掉。已排除的替代路线：Windows 沙箱 `Containers-DisposableClientVM` = **Disabled**；Hyper-V = Enabled 但**无可用虚拟机镜像**。

所以做法是：另造一个**身份不同、且进程清扫段为 no-op** 的试装版，把 NSIS 的安装 / 首启 / 托盘 / 二次启动 / 数据保留 / 卸载全链路**真跑一遍**。它验证的正是 U-01 里真正没人覆盖的部分：安装器机制、文件落盘、注册表、快捷方式、卸载语义。

- `build/installer.pilot.nsh` 中**可执行** `nsExec::Exec … taskkill` 命令数 = **0**（仅注释里提到生产实现）；

## 5. 诚实边界（这节不能省）

**本次没有覆盖、也不声称覆盖的东西：**

1. **生产包的 `DshTerminateAll` 进程清扫段完全没有被执行过。** 它只在「覆盖安装 / 卸载时应用仍在运行」的场景起作用 —— 作用是先关掉正在运行的 DSH Desktop 与后端，避免文件被占用。试装版把这一段换成了 no-op，所以：
   - "安装器能否正确结束正在运行的应用" **仍未验证**；
   - 但要注意：这段清扫与「文件落盘 / 首启 / 托盘 / 二次启动 / 数据保留 / 卸载」**没有因果关系**，后者已在试装版上真实验证。
2. **`perMachine:true` + `allowElevation:true` 的 UAC 提权安装路径未验证**。试装版装到用户目录（无 UAC）；生产包要写 `C:\Program Files` 并弹 UAC，涉及提权、普通用户权限、Program Files ACL —— 这些差异没有被覆盖。
3. 托盘退出（第 4 项）仍是**需人工一步**，与本轮路线无关（Win11 浮层限制）。
4. 试装版与生产版 **AUMID 相同**（因为不允许改产品代码），若将来出现"同一 AUMID 两个安装并存"的通知/托盘归属歧义，本轮无法给出结论。

**建议的 U-01 状态口径（不要写成"通过"）：**

> 「**安装链路已验证（试装版 0.3.50-pilot）**：安装 / 首启 / 关到托盘 / 二次启动 / 数据保留 / 卸载 六项在真实 NSIS 流程下通过，宿主进程全程存活（4/4）。生产包与该试装版的差异 = **身份字符串 + 安装范围（perMachine/UAC） + 进程清扫段**；其中进程清扫段与文件落盘/首启/托盘/卸载无因果关系，perMachine/UAC 提权安装路径仍未验证。」

## 6. 本轮踩到的两个坑（都是"测量错"，不是产品错）

**v1 首轮判了 2 项 FAIL，实际是脚本读错位置** —— 保留过程记录，不掩盖：

| 现象 | 真因 | 修正 |
|---|---|---|
| 等了 420 s 没看到 `lifecycle start` 与 Web UI 地址 → 误判"首启失败" | 生产外壳默认把日志写到**安装目录 `logs`**（`diag-log.js` 的 `installLogsDirCandidate()`），卸载时随目录删除；v1 却去读 `%APPDATA%\…\logs`（不存在）。而 userData 里 `backend/`(35 项)、`dsh-home/`、`startup-recovery.json` 都在 → 应用**确实启动过** | 用 `diag-log.js` 支持的 **`DSH_DIAG_BASE` 测试注入**把日志写到验收目录（`03_调试阶段/试装版安装验收/diag_*/logs`），卸载后仍留存 |
| "后端进程 0 个" | 后端 `node.exe` 落在 **`userData\backend\`**，v1 只按安装目录过滤 | 进程识别改为「安装目录 ∪ userData」双根，且仍**不按映像名模糊匹配**（避免误伤宿主） |

v2 修正后：**PASS 6 / FAIL 0 / 需人工 1**，全程 55 s（v1 已预热 userData 里的后端，首启更快）。
