## 7. 发现：3 条渲染层控制台消息，已定性为「与本安装无关」

安装目录 `logs/DSH-Desktop-错误清单.txt` 里 82 行，其中 62 行是后端 `[tool-scope] denied …` 正常信息流，真正的渲染层消息 3 条：

| 级别 | 内容 | 来源 |
|---|---|---|
| 2 | `[kexi] seat header-utilities via direct failed: slot "conversation.session.header.utilities" is not declared` | 第三方插件 kexi 的 UI 座位机制 |
| 2 | `[kexi] seat settings-card: 全部候选槽位直接注册失败，转入 inject 等待` | 同上（它自己转入了 inject 兜底） |
| **3** | `Uncaught TypeError: Invalid effect` | 一组客户端插件 bundle（`dsh-client-ui-*` / `api-*` / `message-quotes` / `entry-customization` …） |

**为什么判定与本安装无关**（A/B 对照，不是猜）：
- 同一份 0.3.50 代码在**干净 profile**（试装版）跑出的 `错误清单` 只有 9 行，**0 条渲染层消息**（`ERROR_清单` 无 `RENDERER CONSOLE` 记录）；视觉验收 json 里 `consoleErrors: []`。
- 消息来源 URL 是 `http://127.0.0.1:63742/plugins/??…`，这些客户端 bundle 由**你的后端**（仍是 0.2.2-alpha.3，未随安装变化）提供；我们的壳只改了窗口安全策略与日志，不注入页面脚本。
- 因此差异只能来自「你的 profile 里的第三方插件集合」，不是本次安装引入。

**建议排查**（本轮新能力正好能用上）：`plugin-journal.js` 已随 0.3.50 进包，`kexi` 的两个 `seat …` 消息是它自己的座位注册策略与当前 UI 协议不匹配；`Invalid effect` 需要用「逐个禁用第三方插件」定位到具体包。这属于你 profile 的插件兼容问题，我可以另开一轮定位（不动产品代码也能做）。
