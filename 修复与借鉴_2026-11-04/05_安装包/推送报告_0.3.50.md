## 10. 脱敏补提交（2026-11-04 14:12 追加）

lead 复核发现：证据 JSON 里保留着那次进程的**完整本地后端 URL 与 40 字符 token**（`http://127.0.0.1:<port>/?token=<40位>`）。虽然它是**一次性本地会话令牌、进程退出即失效**，但"公开仓库的提交里出现 40 字符 token"本身不合格，故补一次脱敏提交。

### 10.1 做了什么

| 处理 | 范围 | 数量 |
|---|---|---|
| `token=<值>` → `token=<redacted>` | 证据 JSON（`B-05_真机证据_*.json` 等） | 20 处 → 0 处 |
| 本机路径 `C:\Users\<本机用户名>\` → `C:\Users\<user>\` | 证据/文档/CHANGELOG/一处源码注释 | 1 反斜杠 5,245 处、2 反斜杠 1 处、**4 反斜杠 12 处** |
| 新增门禁 `scripts/redact-gate.js` + 白名单 | `scripts/` | 2 个新文件 |
| 入库 `推送报告_0.3.50.md` | `05_安装包/` | 1 个文件 |

合计改动 **129 个文件**；脱敏后校验：全仓 `token=<16+>` 残留 **0 处**（唯一例外是测试夹具，走白名单）、`Users\lcl` 残留 **0 处**、104 个 JSON **全部合法**、被改源码 `updater-backend.js`（仅一处注释）`node --check` 通过。

> 三种反斜杠形态必须按"长→短"顺序替换：证据 JSON 里有些字符串是"JSON 里又嵌了一段 JSON"，路径写成 `C:\\\\Users\\\\lcl\\\\…`（4 个反斜杠）。先替换 2 反斜杠规则会把它切成残缺路径 —— 第一次执行正是因此漏了 6 个文件，重跑时按 4→2→1 顺序才干净。

### 10.2 新增门禁 `scripts/redact-gate.js`

- 阻塞级：`token=<16+>`、`ghp_`、`github_pat_`、`npm_`、`sk-`、私钥块、`AKIA`、`xox*`；命中 **exit 1**。
- 非阻塞告警：仍含 `C:\Users\<具体用户名>\` 的绝对路径（便于降低暴露面）。
- 用法：**每次提交前跑** `node scripts/redact-gate.js`（默认扫暂存区）；例行体检 `--all`；自检 `--selftest`（造一个假 token 验证门禁真的会拦，已通过：`命中 1 处 → ✔ 门禁有效`）。
- 白名单 `scripts/redact-gate.allowlist.json`：只允许**测试夹具**（`test-b04-plugin-journal.js` 里那条夹具，它的断言恰恰是"凭据必须被打码"），且必须写理由；命中白名单**不静默跳过**，门禁以 `ALLOWED` 明示打印。
- 全仓体检结果：扫 405 个文件 → 阻塞 0、白名单放行 1、非阻塞告警 2 处（`C:\Users\Public\Desktop` 通用路径、调查报告中作为**反例**列出的畸形路径 `C:\Users\` + `node_modules` 这类畸形路径，两者都不是本机用户名泄漏）。

### 10.3 诚实边界（重要）

- **历史提交 `c8f6ffe` / `348e5a8` / `b881f67` 里仍然保留着原始 token 与本机路径。** 本次脱敏提交只能让**当前版本**干净；`git log -p` 仍能看到旧值。

- 风险判断：该 token 是后端进程的**一次性本地会话令牌**，只对 `127.0.0.1:<当时端口>` 有效，进程退出即失效，且端口是随机的 → **实际可利用性极低**，但不符合"公开仓库不放凭据形态字符串"的规范。
