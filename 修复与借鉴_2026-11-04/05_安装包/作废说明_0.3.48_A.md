## 3. 作废原因（可复现的完整证据链）

**根因**：electron-builder 打包时会重写应用内的 `package.json`，把 `build` 字段剥离。
而 `main.js:72-73` 在运行期读 `require('./package.json').build.appId` → 成品里恒为 `undefined`
→ `main.js:83` 的 `app.setAppUserModelId(APP_USER_MODEL_ID)` 永不执行。
开发态（`electron .`）读的是源码 package.json，永远是对的 —— 所以单测/门禁全绿也发现不了。

**证据 1：从成品 asar 里取出 package.json（503 字节，无 build 字段）**

```
{
  "name": "dsh-desktop", "productName": "DSH Desktop", "version": "0.3.48",
  "description": "...", "author": "DSH Desktop Packager", "license": "MIT",
  "private": true, "repository": { ... }, "main": "main.js",
  "dependencies": { "electron-updater": "^6.8.9" }
}
```

对照：源码 `package.json` 为 2754 字节，含 `"appId": "com.deepseek.dshdesktop"`。

**证据 2：成品便携实跑的日志原文**
（`修复与借鉴_2026-11-04/03_调试阶段/便携冒烟日志_0.3.48-20261104-0146-6286514/DSH-Desktop-日志.txt`）

```

[..] 通知通道自检（H-08）: {"aumid":"（无）","aumidApplied":false,"platform":"win32","trayBalloonApi":true,"electronNotificationSupported":true,"packaged":true}
[..] 托盘气泡已发出: {"title":"DSH 有可用更新",...,"aumid":null,"platform":"win32","silentDropRisk":"高（未设置 AUMID，系统可能静默丢弃）"}
[..] 托盘气泡已由系统确认显示（balloon-show 已触发）: {"title":"DSH 有可用更新",...,"aumid":null,"platform":"win32"}
```

**证据 3：拦截它的门禁**

上述前两条门禁现已**默认阻断**并串进 `npm run dist`（`--no-strict` 逃生阀会显式打印风险告警）。

## 4. 本机实际影响（如实记录，不夸大）

本机实测气球**仍然显示成功**（`balloon-show` 已触发）—— 也就是说用户在**这台机器上**没有感受到异常。
但 AUMID 保护的意义是"在会吞气泡的系统/策略下也不被静默丢弃"，而这层保护在成品里不存在，
因此 **A 版不满足 H-08 的验收口径**，必须作废，不能以"本机看起来正常"放行。
