## 2. 为什么又出一版（0.3.50 只修一处版式）

0.3.49（C）冻结后，视觉验收在**设置窗**发现一处肉眼可见的排版缺陷：

- **现象**：`后端 Node 要求` 被挤成两行，最后一个字「求」单独掉到第二行，与右侧值「检查更新后显示」错位。
- **根因**：`settings.html` 的 label/value 栅格是**固定列宽** `grid-template-columns: 84px 1fr`；7 字标签在 13px 字号下超过 84px 就折行。`桌面版`/`当前版本`/`最新版本`/`更新状态` 都在 4 字内，所以一直没露头。
- **修法（通用，不做单标签特判）**：
  ```css
  .kv { grid-template-columns: max-content minmax(0, 1fr); column-gap: 10px; }
  .kv .k { white-space: nowrap; }
  .kv .v { min-width: 0; }
  ```
  label 列按内容取宽且禁止换行，值列 `minmax(0,1fr)` 防溢出 —— 以后任何长度的标签都不会折行。

**决策依据**：用户尚未安装任何版本，与其让用户装一个有可感知排版缺陷的 0.3.49，不如修掉重出（成本 ≈ 一次门禁 + 一次打包，约 12 分钟）。0.3.50 相对 0.3.49 **无功能变化**。

### 6.3 纪律：门禁阈值必须能解释成缺陷类型，禁止魔法数字

`字节数 > 51200` 是本次的反例：它和"证据可用"**没有因果关系**。要防的三件事各有精确承担者 ——
「截到别的窗口」→ `captureMethod`；「白屏/纯色占位」→ 像素统计；「写盘截断」→ magic + 尺寸 + 截断下限。
而空工作区首页白底占 79.5%，PNG 天然只有 49 KB —— 50 KB 阈值惩罚的是"界面简单"，换成深色主题立刻误报，也可能放过一张 60 KB 的垃圾图。

现在是：**字节数只做截断下限（8192）**；内容质量由「`domProbe` 锚点（新会话/插件/工作区；设置窗用 更新/设置）+ 像素非空白 + 尺寸对 viewport」共同承担。以后新增阈值必须写明"对应哪种缺陷、为什么是这个数量级"，写不出来不许进流水线。
